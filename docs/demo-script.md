# 8 分钟演示口播稿

> 目标：让评委在 8 分钟内看到「网关双链路 → 工具编排 → RAG 全链路 → 边界兜底」四件事都真实在跑。
> 准备：`pnpm dev` 已启动，浏览器打开 `:5173`，三个健康灯全绿，顶部切到 **proxy**。

## 0:00–0:40 开场（一句话定位）

「这是一个面向中小贸易企业的业务智能体。企业每天要回答三类问题：还有没有货、我的订单到哪了、
保修换货怎么算。我们把它做成一个助手：**能查真实库存和订单、能建售后工单、也能查企业知识库**，
而且每个结论都能点开看到依据。」

指一下右侧面板：「这里会实时显示它调了哪个工具、花了多久、引用了哪份文档。」

## 0:40–1:50 D1/D2 库存（工具 + 多仓 + 替代）

点「D1 查库存」。

「问的是深圳仓 SKU-A1B2C3。注意它没有直接回答『有 25 件』，而是 **可用 17 件** ——
因为在库 25 件里有 8 件已被订单预占。这是库存场景最容易答错的地方。
同时它标出了安全库存 40、在途 100 件、预计 10 月 28 日到货。」

点「D2 跨仓与替代」。

「追问广州仓，它把仓库参数换掉再查一次；发现两仓都不够，给出替代型号和各自可用量。
右侧时间线可以看到两次 `query_inventory` 调用，参数和返回都能展开。」

## 1:50–3:10 D3/D4 订单与写操作（幂等）

点「D3 查订单」。

「它先查订单，再回答状态和物流。这里有一个细节：订购 3 件、已发 2 件，它主动指出了少发。」

点「D4 建工单」。等工单号出现后，**再点一次 D4**。

「第二次返回的是同一张工单，并且标注 `deduplicated: true`。
幂等键不是让模型生成的 —— 模型每次重放都会产生新 uuid，幂等就失效了；
我们由网关按『会话 + 订单 + 类别』派生后注入，模型根本看不到这个字段。
另外如果同订单同类别已有未关闭工单，会直接返回 409 并告知已有单号，避免重复建单。」

## 3:10–4:40 D5 知识库（RAG 全链路）

点「D5 知识问答」。

「保修期和换货条件是两类问题。后端不是一次向量检索就完事：
先做意图路由，再扩写同义词，然后 **多查询检索**（整句 + 每个分段），
过滤后按文档章节去重，最后生成时强制每条结论带 [n] 编号。」

展开右侧引用：「四条来源，点开能看到原文片段和相似度。
这里有个刻意的设计：**纯知识问题由 RAG 直接生成答案，网关不再二次汇总** ——
否则汇总时很容易出现『答案说 A 条款、引用挂 B 文档』的错位。」

## 4:40–6:10 D6/D7 边界（不编造）

点「D6 比特币」。

「红色：超出业务范围。它在路由节点就拒答了，**不检索、不生成**，同时记审计日志。」

点「D7 股权结构」。

「黄色：知识库没有覆盖。注意右侧 trace：`route → rewrite → retrieve → filter → generate → verify`
之后又回到 `rewrite` 重试了两次，还是没证据，于是放弃并建议转人工。
这就是状态图的自适应：成功、重试、放弃三条条件边，重试上限 2 次，不会死循环。」

## 6:10–7:20 D8 故障注入（韧性）

打开顶部「故障注入」，再点 D1。

「现在网关会给业务服务带上 `?chaos=500`。工具调用失败，界面给出错误和重试按钮，
但对话没有卡死，还能继续输入。proxy 链路在这里会重试一次并记录熔断计数。」

关掉注入，点「重试」。

「恢复正常。模型供应商也是同样的思路：主供应商 429/5xx 会退避重试，
再失败切备用供应商，连续失败熔断 15 秒。direct 链路则是一次调用、不重试 ——
两条链路的 SSE 事件完全一致，前端不需要知道后面走的是哪条。」

## 7:20–8:00 收尾（工程化）

「最后说三个工程点：

1. **契约单一真源**：工具 schema、SSE 事件、错误码都写在 shared 包里，
   导出 JSON Schema 给 Python 侧做契约测试，字段漂移由 CI 的契约漂移检查拦截
   （ci.yml 已就位，仓库 git 初始化后首次 push 即生效）；
2. **可复现**：业务数据用固定种子生成，锚点数值写死，评测 36 条跑出「可答用例 31/31 全部命中、
   不可答用例正确拒答 4/5、边界准确率 97.2%」——唯一的失败用例（q34 股价）我们主动披露；
3. **离线可演示**：默认 mock 模型也会真实产生 tool_calls，现场断网也能跑完整链路。」

## 备用问答

- **为什么 direct 也做编排？** 路由文档原写「只鉴权审计」，但那样 direct 下就没有工具时间线，
  且与「两链路事件流一致」冲突。已与需求方确认：两链路都编排，差异只在容灾。
- **为什么不用 AI SDK？** 只有流式 tool_calls 增量与 abort 两件事，手写更可控（见 ADR-003）。
- **embedding 为什么不是 bge？** 默认 hash 保证离线可跑，切 bge 只需改环境变量并重建索引（ADR-007）。
- **十万级文档怎么办？** 当前全量词覆盖扫描需换倒排索引/BM25 服务；接口已抽象成 `Store`，替换不动上层。
