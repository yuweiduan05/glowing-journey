## 2. 切块

| 参数 | 值 | 说明 |
| --- | --- | --- |
| CHUNK_SIZE | 800 | 正文按句打包的**容量上限**（标题感知切块，单节正文通常远小于 800） |
| CHUNK_OVERLAP | 120 | 相邻块重叠从句子边界起算；当前语料单节均 < 800 字，**实测未触发重叠** |
| TABLE_ROW_GROUP | 8 | 表格每 8 行一块，**每块重复表头+分隔行** |

实测（96 块，可对照 `data/chunks.jsonl` 复算）：最短 40 字 / 均值 111 字 / 最长 291 字，
无 ≥500 字的块；84 组相邻块中 0 组产生 ≥20 字重叠（表格块的相邻块会重复表头+分隔行，
属防切断的设计行为，不是 120 重叠）。即 800/120 是**容量上限而非典型值**——
每个小节自成一块，小粒度更利于精确定位与引用溯源；若未来单节正文超过 800 字，
`pack_chunks` 的溢出与 120 重叠分支会自动生效（有单测覆盖）。

三条特殊处理：

1. **标题感知**：`#/##/###` 维护 section_path，写进 metadata（引用面板展示「文档 › 章节」）。
2. **表格**：整表转 Markdown，行组切分；表格块前缀 `【表格】章节名`，便于关键词召回。
3. **不可切分 token**：URL、`SKU-XXXXXX`、`SO-…`、`TK-…`、型号（`PX-200`）、带单位数值
   先替换为占位符，切完再还原，防止「SKU-A1B2C3」被切成两半。

## 3. 检索

```
候选 = 向量 top-N（N = max(top_k*4, 20)，多次查询：整句 + 每个意图分段）
     ∪ 全量词覆盖扫描（coverage ≥ 0.2）
打分 = 0.50*词覆盖 + 0.35*余弦 + 0.15*标题/章节覆盖      （向量召回候选）
     = 0.90*词覆盖 + 0.10*标题覆盖                      （仅词面召回候选）
过滤 = 阈值 0.35 → 按 (doc_id, section) 去重 → top 4
```

为什么加词面召回：哈希 embedding 对「运费怎么算」「S2 多久响应」这类短问句召回不稳定，
纯向量会让精确关键词匹配的块排在 20 名之外，重排阶段根本看不到它。

## 4. manifest 与增量

`data/manifest.json` 记录：版本（sha256 前 12 位）、切块参数、embedding 签名、
每篇文档 sha256 与块数。启动时 `is_fresh()` 四项校验：

1. manifest 存在；2. 签名一致；3. 文档 sha 全一致；4. 向量库 chunk 数 = manifest。

任一项不满足 → 自动重建；全部满足 → `skipped`，启动 < 1s（Chroma 直接加载集合）。

## 5. 评测

`pnpm eval:rag`（36 条：31 条可答 + 2 条 insufficient + 3 条 out_of_scope）：

| 指标 | 实测 | 口径 |
| --- | --- | --- |
| hit@4 | **1.000**（31/31） | **仅统计可答用例**的文档级命中；不可答用例不再「闭嘴就白送」 |
| 拒答正确率 | **0.800**（4/5） | 不可答用例中「边界态判对且无引用」的比例 |
| 边界准确率 | **0.972**（35/36） | 全体用例三态判别 |
| 引用覆盖率 | 1.000 | 可答有引用 / 不可答未误报 |
| 平均耗时 | ≈ 40 ms / 条 | Chroma + hash embedding，纯本地；随负载 35–60ms 波动 |

**已知失败 1 条（如实披露）**：`q34「你们公司在纳斯达克的股价是多少？」` 期望 `out_of_scope`，
实际判为 `insufficient`——越界词表未覆盖「股价」类改写（词表见 `app/boundary.py`）。
其余 4 条不可答用例均正确拒答；31 条可答用例全部命中。

「状态图自适应」的正样本：`q31「售后工单摘要必须写清哪些内容？」` 首轮 top1 仅 0.31、
低于阈值 0.35；第 1 次重试切换改写策略（去疑问词 + 同义词 + 泛化词）后 top1 回到 0.39，
判为 `in_kb`——trace 中可见两轮 rewrite/retrieve（`data/eval/report.json` 可复查）。

**可复现性**：打分平局一律按 `chunk_id` 次级决胜（`retrieval.py` 的 `search`/`apply_filter`）——
chroma 对等距结果的返回顺序不保证稳定，只按分数排序会让 margin 用例在多次评测间偶发漂移
（曾实测到 q17 第 4 槽位平局漂移）。加上次级键后，连续多次评测输出逐字节一致。

报告落在 `data/eval/report.json`，含每条用例的命中情况、来源与耗时，可直接截图。
入库时同步导出 `data/chunks.jsonl`（chunk_id → 文档/章节/序号/原文），
便于离线复算 chunk 级指标，也便于第三方抽查引用是否真实存在。
